# Build-time decisions

Several inputs and hardcoded values pick a Google Cloud resource's shape once,
at create time. Changing them later on an existing deployment either forces
Terraform (or the underlying API) to replace the resource, destroying and
recreating it with downtime and possible data loss, or the Google Cloud API
rejects the change outright. This page pulls that information together in one
place; it does not cover every input, only the ones verified against the
`hashicorp/google` provider source/docs and this module's own code.

Each row cites the `google_*` resource argument or GCP behavior backing the
claim, plus the module file/line where the input is wired in.

| Module input (or hardcoded value) | Underlying argument | What happens if you change it on an existing deployment | Guidance |
| --- | --- | --- | --- |
| `gcp_region` (used as the GKE cluster's `location`) | `google_container_cluster.location` is `ForceNew` in the provider schema[^gke-location] | Terraform destroys and recreates the whole cluster (and, transitively, the node pool) in the new region. | Pick the region deliberately at first apply ([gke.tf:35](../gke.tf#L35)). There is no in-place region migration; stand up a new cluster/region and migrate workloads. |
| `gke_control_plane_cidr` (effective only when `gke_enable_private_nodes = true`) | `google_container_cluster.private_cluster_config.master_ipv4_cidr_block` is `ForceNew`[^gke-master-cidr] | Terraform replaces the cluster. | Size this `/28` range correctly before the first apply ([gke.tf:108-112](../gke.tf#L108-L112)); it cannot be resized or moved later. |
| `gke_enable_private_nodes` | Converting a cluster's nodes from public to private (or back) after creation is not supported by the GKE API; Google states you must recreate the cluster[^gke-private-convert] | Flipping this on an existing public-node cluster requires deleting and recreating the cluster. | Decide the private-nodes posture at first apply ([gke.tf:109](../gke.tf#L109)). |
| Hardcoded `datapath_provider = "ADVANCED_DATAPATH"` (Dataplane V2) | `google_container_cluster.datapath_provider` is `ForceNew`[^gke-datapath] | Any cluster still on `LEGACY_DATAPATH` (pre-dataplane-v2) forces a full replacement when this module (or a Google provider upgrade) applies Dataplane V2. | Already called out in [gke.tf:76-83](../gke.tf#L76-L83) and [`docs/upgrading-n8n.md`](./upgrading-n8n.md#gke-dataplane-v2-requires-cluster-replacement); read that section before applying to existing state. |
| `gke_node_type`, `gke_node_disk_size_gb`, `gke_node_disk_type` | `google_container_node_pool.node_config.machine_type` / `disk_size_gb` / `disk_type` are `Optional, Computed` with **no** `ForceNew` and **no** corresponding field in the provider's node-pool update path[^gke-nodeconfig-update] | The provider neither replaces the node pool nor actually applies the change: `terraform apply` succeeds but the running node pool silently keeps its old machine type/disk shape (a confirmed provider gap[^gke-machine-type-ignored]). | Wired in [gke.tf:187-189](../gke.tf#L187-L189). To really change node shape, add a new `google_container_node_pool` (a module fork or an out-of-band resource) with the new shape, drain the old pool, then remove it; do not expect changing these variables alone to do anything. |
| `subnet_cidr` | `google_compute_subnetwork.ip_cidr_range` is **not** `ForceNew`, but its only update path is the `expandIpCidrRange` API, which grows a range and **rejects shrinking it**[^subnet-ipcidr] | Growing the range works in place; choosing a smaller range later is rejected by the API. | Size [`subnet_cidr`](../network.tf#L47) generously up front. |
| `pods_cidr` / `services_cidr` | The subnetwork's `secondary_ip_range` entries are updatable via the API, but the GKE cluster's `ip_allocation_policy.cluster_secondary_range_name` / `services_secondary_range_name` pin *which* named range the cluster uses, and those are read once at cluster creation[^gke-ip-alloc] | Resizing an unused secondary range is possible at the subnetwork level, but changing which range (or its size) the running cluster's pods/services actually use requires replacing the cluster. | Wired in [network.tf:50-57](../network.tf#L50-L57) and consumed by [gke.tf:53-56](../gke.tf#L53-L56); size pod/service ranges for the cluster's lifetime, not just today's node count. |
| `gcp_region` as the VPC subnet's `region` | `google_compute_subnetwork.region` is `immutable` (ForceNew) in the resource definition[^subnet-region] | Terraform replaces the subnet (and every resource that references it). | Set once in [network.tf:45](../network.tf#L45). |
| `psa_prefix_length` (Private Services Access peering range) | `google_compute_global_address` is `immutable` at the resource level in the provider's resource definition, so every argument (including `prefix_length`) forces replacement[^psa-immutable] | Terraform destroys and recreates the global address, which requires re-peering Cloud SQL/Memorystore through it. | Set in [network.tf:123-131](../network.tf#L123-L131); pick a prefix length that leaves headroom for both Cloud SQL and Memorystore before the first apply. |
| `postgres_edition` | Cloud SQL's `settings.edition` has no documented in-place downgrade path; the module pins `tier`/`edition` compatibility at creation (see the resource's own curated-exception comment) | Switching `ENTERPRISE` ⇄ `ENTERPRISE_PLUS` is a one-way, tier-compatibility-constrained operation, not a safe toggle. | Set in [cloudsql.tf:119](../cloudsql.tf#L119); confirm the target `postgres_machine_type` is valid for the new edition before changing this on a live instance. |
| `gcp_region` as the Cloud SQL instance's `region` | Google's own Cloud SQL documentation states the region "can only be set during instance creation" and "can't be changed after the instance is created"[^cloudsql-region] | There is no in-place region change; Google's documented migration paths are a cross-region read replica promoted to primary, or export/import. | Set in [cloudsql.tf:102](../cloudsql.tf#L102). |
| Cloud SQL `private_network` (always `local.effective_network_id`) | Moving a Cloud SQL instance from private IP back to public (or vice versa) is a known unsupported transition at the provider/API level[^cloudsql-private-network] | Changing which VPC an instance is privately peered into is not a supported in-place operation. | Decide the network (`create_network` / existing VPC) before first apply; see [cloudsql.tf:126-130](../cloudsql.tf#L126-L130). |
| `redis_tier` | `google_redis_instance.tier` is `immutable` in the resource definition[^redis-immutable] | Terraform replaces the Memorystore instance (full data loss unless `redis_persistence_enabled` and a restore are used). | Set in [memorystore.tf:39](../memorystore.tf#L39). |
| `gcp_region` as the Memorystore instance's `region` | `google_redis_instance.region` is `immutable`[^redis-immutable] | Terraform replaces the instance. | Set in [memorystore.tf:38](../memorystore.tf#L38). |
| Hardcoded `connect_mode = "PRIVATE_SERVICE_ACCESS"` | `google_redis_instance.connect_mode` is `immutable`[^redis-immutable] | N/A today (the module never varies this), but a future change to expose it as a variable would force replacement on flip. | [memorystore.tf:44](../memorystore.tf#L44). |
| `redis_auth_enabled` | `google_redis_instance.auth_enabled` is `immutable`[^redis-immutable] | Turning Redis AUTH on or off after creation replaces the instance, not an in-place toggle as the variable description implies. | [memorystore.tf:45](../memorystore.tf#L45); decide AUTH posture before first apply. |
| `redis_transit_encryption_enabled` | `google_redis_instance.transit_encryption_mode` is `immutable`[^redis-immutable] | Turning in-transit TLS on or off after creation replaces the instance. | [memorystore.tf:46](../memorystore.tf#L46). |
| Memorystore/Cloud SQL/GCS CMEK (`create_*_kms_key` / `existing_*_kms_key_id`) | `google_redis_instance.customer_managed_key` is `immutable`[^redis-immutable]; Cloud SQL's `encryption_key_name` and the GCS `encryption` block only take effect at resource creation per this module's own code comments | CMEK can only be set when the Cloud SQL instance / Memorystore instance / GCS bucket is first created; it is never mutated on an existing one. | [kms.tf:90](../kms.tf#L90) (Cloud SQL), [kms.tf:132](../kms.tf#L132) (Redis), [kms.tf:175](../kms.tf#L175) + [gcs.tf:135-140](../gcs.tf#L135-L140) (GCS). |
| `gcs_location` | Google's `google_storage_bucket` documentation states "once a bucket has been created, its location can't be changed"[^gcs-location] | No in-place change; the bucket (and all its objects) must be recreated in the new location. | Set in [gcs.tf:63](../gcs.tf#L63) and [gcs.tf:101](../gcs.tf#L101) for both the binary-data bucket and its access-log bucket. |
| `n8n_encryption_key` (or the module-generated key when left `null`) | n8n encrypts stored credentials with this key; it is never rotated or re-derived by this module | Changing the effective key (new value, or regenerating by recreating the core Secret) makes every previously stored n8n credential undecryptable. | Generated once in [n8n.tf:8-12](../n8n.tf#L8-L12); back it up as part of every upgrade per [`docs/upgrading-n8n.md`](./upgrading-n8n.md) step 1, and see [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md#L331-L339) for the restore/clone reconciliation procedure if you need to recover credentials encrypted under an old key. |
| `n8n_fqdn` | Not a Terraform `ForceNew`, but changing it rotates the `google_dns_record_set.n8n` resource-instance key (hostname-keyed `for_each`) and the ManagedCertificate/ingress host it is wired to | DNS propagation delay, a new TLS certificate issuance, and (on a pre-20.2 state) a documented manual `terraform state mv` to avoid an unnecessary record delete/recreate. | [dns.tf:38-56](../dns.tf#L38-L56); see that file's own comment and [`docs/upgrading-n8n.md`](./upgrading-n8n.md) task 26.1 for the state-move procedure. |

[^gke-location]: [`google_container_cluster`](https://github.com/hashicorp/terraform-provider-google/blob/main/google/services/container/resource_container_cluster.go) schema: `"location": {..., ForceNew: true}`.
[^gke-master-cidr]: Same file, `private_cluster_config.master_ipv4_cidr_block` schema: `ForceNew: true`; the provider's `expandPrivateClusterConfigMasterIpv4CidrBlock` comment states "master_ipv4_cidr_block is immutable."
[^gke-private-convert]: [GKE: Customize your network isolation](https://cloud.google.com/kubernetes-engine/docs/how-to/private-clusters) and [About cluster configuration choices](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/configuration-overview): "Many of the options discussed... can't be changed after a cluster is created... you must create a new cluster then migrate traffic to it."
[^gke-datapath]: `resource_container_cluster.go` schema: `"datapath_provider": {..., ForceNew: true}`.
[^gke-nodeconfig-update]: `node_config.go` schema entries for `machine_type`, `disk_size_gb`, `disk_type` are `Optional, Computed` with no `ForceNew` flag; `resource_container_node_pool.go`'s `resourceContainerNodePoolUpdate` has no code path referencing `machine_type`, `disk_size_gb`, or `disk_type`.
[^gke-machine-type-ignored]: [hashicorp/terraform-provider-google#23502](https://github.com/hashicorp/terraform-provider-google/issues/23502): "changes to node_config.machine_type are ignored... apply was successful... but the actual node_pool never updated."
[^subnet-ipcidr]: [magic-modules `Subnetwork.yaml`](https://github.com/GoogleCloudPlatform/magic-modules/blob/main/mmv1/products/compute/Subnetwork.yaml): `ipCidrRange` has `update_url: .../expandIpCidrRange` (grow-only; the API rejects a smaller range).
[^gke-ip-alloc]: `google_container_cluster.ip_allocation_policy.cluster_secondary_range_name` / `services_secondary_range_name` are read at cluster creation (no update path in the cluster resource); this module sets them from the subnet's secondary ranges in [gke.tf:53-56](../gke.tf#L53-L56).
[^subnet-region]: `Subnetwork.yaml`: `region` field has `immutable: true`.
[^psa-immutable]: [magic-modules `GlobalAddress.yaml`](https://github.com/GoogleCloudPlatform/magic-modules/blob/main/mmv1/products/compute/GlobalAddress.yaml): resource-level `immutable: true` (no field overrides it), so every argument including `prefix_length` forces replacement.
[^cloudsql-region]: [Cloud SQL: About instance settings](https://docs.cloud.google.com/sql/docs/mysql/instance-settings): "You can only set the region during instance creation." [Manage instance locations](https://docs.cloud.google.com/sql/docs/mysql/locations): "The location can't be changed after the instance is created."
[^cloudsql-private-network]: [hashicorp/terraform-provider-google#2964](https://github.com/hashicorp/terraform-provider-google/issues/2964): going from private to public (or the reverse) is not a supported update; the API returns an error.
[^redis-immutable]: [magic-modules `Instance.yaml`](https://github.com/GoogleCloudPlatform/magic-modules/blob/main/mmv1/products/redis/Instance.yaml) (Memorystore for Redis): `tier`, `region`, `connectMode`, `authEnabled`, `transitEncryptionMode`, and `customerManagedKey` are each marked `immutable: true`.
[^gcs-location]: [`google_storage_bucket`](https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/storage_bucket): "Once a bucket has been created, its location can't be changed."
