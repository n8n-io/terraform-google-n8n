# Shared responsibility

This module creates and configures an opinionated slice of Google Cloud
infrastructure for n8n: GKE, a Google Cloud L7 load balancer (native `gce`
Ingress), Cloud SQL for PostgreSQL, Memorystore for Redis, a GCS bucket, and
the n8n Helm release. It does not, and is not intended to, run the whole
platform for you. This page collects the ownership boundaries that are
otherwise scattered across the README's "Out of scope" section, individual
variable descriptions, and several other docs, into one table so a platform
partner pricing a build on top of the module can find every gap in one
place.

Read this alongside
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md),
which documents the caller-managed *layers* (network/PSA, GKE, Cloud SQL,
Memorystore, GCS, namespace, ingress, autoscaling) this module can hand off
entirely. The rows below cover responsibilities that exist regardless of
which layer ownership mode is selected.

| Area | What the module does | What the caller owns | Related input / doc |
|---|---|---|---|
| Cluster security add-ons and policy | Creates the GKE cluster (or attaches to an existing one) with Workload Identity, Dataplane V2, shielded nodes, intranode visibility, and an optional control-plane authorized-networks allowlist. | Binary Authorization (Checkov `CKV_GCP_66`), RBAC via Google Groups (`CKV_GCP_65`), GKE application-layer secrets encryption (a KMS-backed `database_encryption` block), and the Security Posture dashboard are not enabled by the module; the first two require platform decisions (an attestor pipeline, an existing Cloud Identity group) this module does not own, and the others are not wired at all. Enable them against the resulting cluster out of band, or fork `gke.tf`. | `gke_control_plane_authorized_networks`; [`gke.tf`](../gke.tf) (see the `CKV_GCP_65`/`CKV_GCP_66` resource comments) |
| Network egress and DNS | Creates a Cloud Router + Cloud NAT for egress from private nodes when `create_network = true`, and an optional Google Cloud DNS A-record per ingress hostname when `cloud_dns_zone_name` is set. | No egress firewall beyond the explicit deny-all-ingress rule (no egress allowlist) is created; outbound traffic from the cluster is unrestricted beyond Cloud NAT's own behavior unless the caller adds a firewall policy. An alias whose DNS is delegated elsewhere (a different Cloud DNS zone, or another provider), and DNS for an externally supplied PostgreSQL/Redis endpoint, are also the caller's responsibility, the same way [`examples/cloudflare`](../examples/cloudflare) and [`examples/godaddy`](../examples/godaddy) already manage the canonical record out of band. | `cloud_dns_zone_name`, `n8n_additional_domains`; [`network.tf`](../network.tf), [`dns.tf`](../dns.tf) |
| Edge protection | When `create_ingress = true`, can create a Cloud Armor security policy restricting the load balancer to `ingress_source_cidrs`, or attach an `existing_cloud_armor_policy_name`. | Source restriction is opt-in: with neither input set, the load balancer accepts traffic from any source. WAF rule tuning, rate limiting, and bot management beyond basic IP allowlisting are the caller's responsibility. | `ingress_source_cidrs`, `existing_cloud_armor_policy_name`; [`dns.tf`](../dns.tf) |
| TLS | Selects a certificate source via `tls_mode`: `google_managed` (a `ManagedCertificate` CR), `custom` (caller-supplied PEM), or `self_signed` (module-generated). | `tls_mode = secret` consumes an externally managed Kubernetes Secret the caller creates and rotates; certificate issuance, renewal, and trust-store distribution for `custom`/`secret` mode are the caller's job. With `create_ingress = false`, TLS termination is the caller's entirely. | `tls_mode`; [README, TLS](../README.md#tls-tls_mode) |
| Secrets and Terraform state | Generates the Cloud SQL password (`random_password.db_password`), the n8n encryption key (`random_id.n8n_encryption_key`, unless `n8n_encryption_key`/`existing_n8n_core_secret_name` is set), the task-runner token (`random_password.task_runner_token`), and the GCS HMAC key (`google_storage_hmac_key.n8n`) as Terraform-managed values. | Every generated or caller-supplied value the module does not receive through a `*_secret_ref` (or an existing-Secret input) lands in Terraform state on the default path: the Cloud SQL password, the generated n8n encryption key (unless `existing_n8n_core_secret_name` is set), `n8n_encryption_key` when supplied directly, the task-runner token (which has no `*_secret_ref` opt-out), `n8n_license_key` when `n8n_license_key_secret_ref` is unset, `n8n_database_password` when `create_postgres_instance = false` and `n8n_database_password_secret_ref` is unset, `redis_password` when `redis_password_secret_ref` is unset, and the GCS HMAC secret when neither `gcs_hmac_secret_name` nor BYO-HMAC-via-existing-Secret is used. Use `n8n_license_key_secret_ref`, `n8n_database_password_secret_ref`, `redis_password_secret_ref`, `existing_n8n_core_secret_name`, `n8n_credentials_overwrite_secret_ref`, and `gcs_hmac_secret_name` to keep the corresponding value out of state. | [`cloudsql.tf`](../cloudsql.tf), [`n8n.tf`](../n8n.tf), [`gcs.tf`](../gcs.tf); the `*_secret_ref` variables in `variables.tf` / `variables_gcp.tf` |
| Backup and restore | Module-managed Cloud SQL instances have automated backups and point-in-time recovery enabled by default; Memorystore persistence (RDB snapshots) is opt-in (`redis_persistence_enabled`); GCS object versioning is enabled on the module's bucket by default (noncurrent versions capped at the three most recent). | The caller must configure and verify backups for externally managed PostgreSQL (`create_postgres_instance = false`). Restore testing, cross-region backup copy, n8n encryption-key escrow, and any backup for Redis or GCS data beyond what those opt-in switches provide are not automated. Memorystore's RDB persistence is a last-snapshot restart aid, not a numbered backup history. A restore or clone onto a module-managed Cloud SQL instance does not carry over the original encryption key. Build a DR runbook around the managed services' native capabilities. | `redis_persistence_enabled`; [README, Out of scope](../README.md#out-of-scope), [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md#restoredcloned-database-encryption-key-continuity), [`docs/post-deployment.md`](./post-deployment.md) |
| Observability | Wires n8n's built-in Prometheus metrics endpoint, OpenTelemetry trace export, log streaming, and an optional Redis-queue-depth exporter when the caller configures them. | The module installs no Prometheus, Grafana, Loki, or OpenTelemetry Collector, and no alert rules or dashboards; point the exporters it ships at your own monitoring stack. | `n8n_metrics_enabled`, `redis_exporter_enabled`, `n8n_otel_exporter_otlp_endpoint`; [`observability.tf`](../observability.tf), [README, Out of scope](../README.md#out-of-scope) |
| Upgrades | Supports bumping `n8n_image_tag` / the pinned n8n Helm chart version on an existing deployment, with per-version upgrade notes; the GKE release channel (`gke_release_channel`) keeps the control plane and nodes on Google's own cadence. | Database migration rollback on a failed upgrade is not automatic: n8n's own migrations run forward-only, so a caller who needs to roll back restores from a Cloud SQL backup taken before the upgrade. The Dataplane V2 migration (LEGACY_DATAPATH to ADVANCED_DATAPATH) forces cluster replacement and is a manual, caller-timed operation. | `gke_release_channel`; [`docs/upgrading-n8n.md`](./upgrading-n8n.md) |
| Licence | Requires and wires an n8n Enterprise license key (direct value or Secret reference) for multi-main; does not provision a community-edition deployment. | Obtaining and renewing the n8n Enterprise license, and any n8n support entitlement tied to it, is the caller's responsibility (this module and n8n's own enterprise support are separate). | `n8n_license_key`, `n8n_license_key_secret_ref`; [README, Prerequisites](../README.md#4-enterprise-license) |
| Quotas and project prerequisites | Ships [`scripts/preflight.sh`](../scripts/preflight.sh), a read-only check of the APIs and IAM permissions the module needs. | Regional GKE node, Cloud SQL, and Memorystore quota increases, and the `iam.disableServiceAccountKeyCreation` org policy decision the GCS HMAC key needs, are the caller's to request/clear before `apply`; the module does not request quota or relax org policy on its own (`manage_sa_key_org_policy` is an explicit opt-in). | [README, Prerequisites](../README.md) |

This page does not repeat the full ownership contract for caller-managed
network/PSA, GKE, Cloud SQL, Memorystore, the GCS bucket, the namespace, or
ingress, see
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md)
for those.
