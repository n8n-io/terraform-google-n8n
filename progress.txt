## 2026-07-23 - update-module-to-hvd-conventions - 1. Naming foundation
- Replaced `cluster_name` with `friendly_name_prefix` (required, validated: no
  "n8n" substring, RFC1035 charset, <= 30 chars) as the naming driver for every
  GCP resource. Added `common_labels` (map(string), default {}, HVD label
  charset validation), merged into `local.gcp_labels` in network.tf.
- Introduced `local.name_prefix = "${var.friendly_name_prefix}-n8n"` in
  locals.tf, replacing `local.cluster_name`. Mechanical find/replace of
  `local.cluster_name` -> `local.name_prefix` across cloudsql.tf, dns.tf,
  gke.tf, memorystore.tf, network.tf, workload_identity.tf, gcs.tf works
  directly because existing suffixes (`-pg`, `-redis`, `-pool`, etc.) stay the
  same string once the base local already includes `-n8n`.
- Exception: the GCS bucket name keeps `<project_id>-n8n-<friendly_name_prefix>`
  (uses `var.friendly_name_prefix` directly, not `local.name_prefix`) to avoid
  a doubled "-n8n" and to preserve global-uniqueness semantics. Design D1 calls
  this out explicitly; don't mechanically replace that one.
- Renamed outputs `cluster_name`/`cluster_endpoint`/`cluster_ca_certificate` to
  `gke_cluster_name`/`gke_cluster_endpoint`/`gke_cluster_ca_certificate`.
  Updated every example's providers.tf (`module.n8n.cluster_endpoint` etc.).
- Updated all five examples' main.tf/variables.tf/terraform.tfvars.example for
  the `friendly_name_prefix` rename; example defaults must not contain "n8n"
  (e.g. "dev", "medium", "large", "godaddy") or the new validator rejects them.
- Root `tests/defaults.tftest.hcl`: renamed `cluster_name` variable/tests to
  `friendly_name_prefix`, updated derived-name assertions (GCS bucket, SA
  account_ids), added `common_labels` propagation assertions on
  `google_container_cluster.n8n.resource_labels`, and validator rejection runs
  (uppercase, trailing hyphen, leading digit, "n8n" substring, > 30 chars).
- **Learnings for future iterations:**
  - GKE cluster/node-pool names and (assumed) Memorystore instance IDs share a
    40-character GCP limit; with `local.name_prefix` already appending "-n8n"
    (4 chars), the tightest additional suffix is `-redis` (6 chars), which is
    why `friendly_name_prefix` is capped at 30. Document this arithmetic in the
    validator error message per design D1's instruction.
  - `terraform-docs .` must be re-run in the module root AND every example
    after any variable/output rename; each example has its own generated
    README block.
  - Local dev artifacts (`examples/small/terraform.tfvars`,
    `terraform.tfstate*`) are gitignored but still get picked up by
    `terraform validate`/`test`; update the stale variable name there too so
    the local loop doesn't warn, but never touch committed secrets.
  - `git grep <old-name>` after a rename still turns up prose in README.md,
    AGENTS.md, docs/*.md - those are explicitly section 5 (operator docs) in
    this change's task breakdown; leave them for that section rather than
    fixing prose ahead of schedule.

## 2026-07-23 - update-module-to-hvd-conventions - 3. Redis and GKE interface rename
- Renamed Memorystore variables to HVD-style names per design D3:
  `memorystore_tier` -> `redis_tier`, `memorystore_memory_gb` ->
  `redis_memory_size_gb`, `memorystore_redis_version` -> `redis_version`,
  `memorystore_auth_enabled` -> `redis_auth_enabled`. Renamed node/GKE
  variables: `node_machine_type` -> `gke_node_type`, `node_min_per_zone` ->
  `gke_node_min_per_zone`, `node_max_per_zone` -> `gke_node_max_per_zone`,
  `node_disk_size_gb` -> `gke_node_disk_size_gb`, `node_disk_type` ->
  `gke_node_disk_type`, `cluster_deletion_protection` ->
  `gke_deletion_protection`, `enable_private_nodes` ->
  `gke_enable_private_nodes`, `master_ipv4_cidr` -> `gke_control_plane_cidr`,
  `master_authorized_networks` -> `gke_control_plane_authorized_networks`.
  Renamed output `memorystore_host` to `redis_host`.
- Updated `memorystore.tf`, `gke.tf`, `n8n.tf`, `keda.tf` (comments too),
  `variables_gcp.tf`, `outputs.tf`; updated all five examples'
  `main.tf`/`variables.tf`/`terraform.tfvars.example`; updated
  `tests/defaults.tftest.hcl`. Regenerated terraform-docs at root and every
  example. Added CHANGELOG bullets under `## [Unreleased] / ### Changed`.
- **Learnings for future iterations:**
  - A single word-boundary regex rename script across `*.tf`,
    `examples/*/*.tf`, `examples/*/*.tfvars.example`, and
    `tests/*.tftest.hcl` in one Python pass works well for a batch of
    unrelated renames, but it is blind to context: it will also rewrite a
    Google resource schema attribute *key* that happens to share the exact
    variable name being renamed. Here `enable_private_nodes` is both our
    variable name and the literal attribute key inside
    `google_container_cluster.private_cluster_config {}`; the script turned
    `enable_private_nodes = var.enable_private_nodes` into
    `gke_enable_private_nodes = var.gke_enable_private_nodes`, which is
    invalid (the resource schema doesn't have that attribute). Caught by
    `terraform validate` immediately after the mechanical pass. Always run
    `terraform validate` right after a mechanical rename and diff every
    changed `resource` block by eye for a rewritten attribute key, not just
    the intended `var.xxx` reference.
  - None of the five example `tests/defaults.tftest.hcl` files or
    `examples/small/terraform.tfvars` referenced any of this section's old
    names, so no test file needed manual editing beyond the root
    `tests/defaults.tftest.hcl` (which the mechanical script already
    covered).
